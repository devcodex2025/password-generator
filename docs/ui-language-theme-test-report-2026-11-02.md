## 2. Виявлені проблеми

### P1. Низький контраст логотипу в темній темі

**Серйозність:** середня, доступність  
**Локація:** логотип у хедері та футері, темна тема  
**Причина:** в обох темах використовується один і той самий `logo.svg`, де основний колір — темно-синій `#2A4E63`.

**Доказ:**

- фон хедера/футера в темній темі: `#121212`;
- контраст основного напису `#2A4E63` на `#121212`: **2.11:1**;
- контраст світло-блакитних елементів `#E5F6FF` на `#121212`: **16.91:1**.

**Вплив:** напис `generate` і дрібний `PASSWORDTO.ME` погано читаються на темному фоні. Для великого тексту рекомендовано щонайменше 3:1, для дрібного — 4.5:1 (WCAG 1.4.3 / 1.4.11).

**Варіанти виправлення:**

1. Додати світлу підкладку/плашку під логотип у темній темі — логотип залишається тим самим файлом.
2. Застосувати CSS-фільтр (`brightness`/`invert`) лише в темній темі — візуально це вже інший колір.
3. Повернути окремий світлий варіант логотипу — суперечить поточному рішенню використовувати один логотип.

**Критерії готовності:**

- контраст основного напису ≥ 3:1, дрібного — ≥ 4.5:1;
- логотип не змінює форму/пропорції;
- перевірено хедер і футер у світлій і темній темах;
- немає помітного layout shift.

### P2. React-попередження про `<script>` під час клієнтського переходу між мовами

**Серйозність:** низька, гігієна консолі / SEO  
**Локація:** клієнтська навігація `ua ↔ en` на головній сторінці

**Повідомлення:**

```text
Encountered a script tag while rendering React component. Scripts inside React components are never executed when rendering on the client. Consider using template tag instead.
```

**Відтворення:**

1. Відкрити `/ua`.
2. Перемкнути мову на `en` (десктопний селект або drawer).
3. Відкрити консоль браузера.

**Вплив:** попередження з'являється лише під час client-side навігації; на прямому завантаженні `/` його немає. UI не ламається. Ймовірно, пов'язано з JSON-LD `<script>` у layout (`HomeStructuredData`) або скриптами в `[locale]/layout.tsx`, які потрапляють у клієнтське дерево під час переходу.

**Що перевірити/виправити:**

- переконатися, що JSON-LD присутній у серверному HTML після прямої навігації;
- винести JSON-LD у серверну межу, яка не ререндериться на клієнті, або використати рекомендований Next.js підхід для structured data;
- перевірити, чи попередження зникає у production-build;
- додати регресійну перевірку: перемикання мови не дає помилок у консолі, JSON-LD не зникає.

**Критерії готовності:**

- під час `ua ↔ en` у консолі немає цього попередження;
- JSON-LD валідний і присутній у HTML;
- немає hydration mismatch.

### P3. Попередження Next/Image про пропорції банера NordPass

**Серйозність:** низька, візуальна / гігієна консолі  
**Локація:** головна сторінка, англійська локаль, банер `/affiliate/nordpass-en-728x90.png`

**Повідомлення:**

```text
Image with src "/affiliate/nordpass-en-728x90.png" has either width or height modified, but not the other. If you use CSS to change the size of your image, also include the styles 'width: "auto"' or 'height: "auto"' to maintain the aspect ratio.
```

**Відтворення:**

1. Відкрити англійську головну `/`.
2. Дочекатися завантаження банера NordPass.
3. Перевірити консоль.

**Вплив:** банер може втрачати пропорції на окремих breakpoint-ах; попередження засмічує консоль. Проблема не пов'язана з темою чи мовою безпосередньо — вона проявляється під час ререндеру банера.

**Що перевірити/виправити:**

- перевірити `AffiliateBanner` і місця рендеру банерів у статтях;
- переконатися, що разом із `w-full` є `h-auto` (або навпаки), або використати `fill`/`sizes` коректно;
- перевірити співвідношення 728×90 на мобільних і десктопі.

**Критерії готовності:**

- попередження зникає;
- банер зберігає пропорції 728:90 на всіх breakpoint-ах;
- немає візуального стрибка під час завантаження.
