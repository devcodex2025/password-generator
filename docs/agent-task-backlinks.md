# Завдання агенту: виконати лінкбілдинг-прогін і звітувати

> Цей файл — готове ТЗ. Передайте агенту рядком: «Виконай завдання з `docs/agent-task-backlinks.md` повністю, автономно, і в кінці дай звіт за формою з розділу 6».

---

## 0. Контекст

Репозиторій: генератор паролів `generatepasswordto.me` (Next.js, 11 мов).
Домен новий. Мета — не «багато посилань», а 5–10 якісних referring domains за 30 днів без ризику manual action.

У репозиторії вже є:

- `docs/backlink-sources.csv` — 256 джерел із tier, пріоритетом, типом лінка й статусом;
- `docs/backlink-sources-2026-11.md` — стратегія, шаблони, правила;
- `docs/backlink-queue.md` — згенерована черга;
- `docs/link-building-tracking.json` — лог розміщень;
- `docs/backlink-catalogs.json` — результати попереднього тесту 40 сервісів;
- `scripts/backlink-queue.mjs` — перевірка живості, черга, верифікація лінка.

---

## 1. Мета і межі

**Мета:** виконати все, що можна зробити автономно, без створення акаунтів, без captcha, без участі людини; верифікувати кожен опублікований лінк; підготувати людині точний список наступних дій; дати звіт із доказами.

**Автономно можна:**

- читати/аналізувати файли репозиторію;
- запускати `scripts/backlink-queue.mjs` (перевірка, черга, верифікація);
- робити HTTP-запити до публічних API та сторінок;
- публікувати **тільки** на платформах, де публікація без акаунта дозволена явно (Telegraph API; інші — лише якщо API підтверджено документацією);
- оновлювати CSV, tracking-файл, чергу та створювати звіт.

**Автономно не можна (позначати `blocked`, не намагатися обійти):**

- створювати акаунти, входити в існуючі, використовувати чужі сесії;
- проходити captcha, Cloudflare-челенджі, email-верифікацію;
- постити в Reddit, HN, DOU, Stack Exchange та інші спільноти;
- масово реєструватися з тимчасовою поштою;
- платити, вводити платіжні дані, приймати ToS від імені власника;
- змінювати `src/`, білд, залежності, CI.

Якщо крок вимагає логіну або captcha — **не обходити**, а зафіксувати в розділі «Заблоковано» звіту.

### 1.1. Виняток для каталогів (рішення власника, 2026-11-02)

Власник явно дозволив обмежений прогін із **однією** поштовою скринькою, до якої зберігається доступ. Це не скасовує заборону на captcha й масовість; діють такі ліміти:

- одна скринька на прогін, доступ до неї зберігається до кінця кампанії (не «викинути після реєстрації»);
- ціль — **до 10 успішних реєстрацій/подань за кампанію**; максимум **10 реєстрацій за прогін**, лише каталоги/launch-платформи, які дають публічну сторінку з посиланням;
- «успіх» = акаунт створено + лiстинг подано; лінк зараховується лише після `--verify` з `found ≥ 1`;
- captcha, Cloudflare-челенджі та платні тарифи не обходяться — такий каталог позначається `blocked`;
- жодних платіжних даних; ToS приймається лише там, де без цього неможлива безкоштовна реєстрація, і це фіксується в лозі;
- облікові дані зберігаються у gitignored-файлі (`secrets/`, шаблон `secrets/gmail-access.json`), який ніколи не комітиться і не потрапляє у звіти; після кампанії пароль відкликається, файл видаляється;
- кожен акаунт логується в `docs/link-building-tracking.json` зі статусом `account_created` / `pending`.

Правила з розділу 4 (безпека, відсутність секретів) і розділу 7 (умови зупинки) лишаються чинними.

## 3. Фази

### Фаза 1 — Аудит джерел (обов'язково)

```bash
node scripts/backlink-queue.mjs --check
```

Результат: `docs/backlink-sources.checked.csv`.

Далі:

- Усі рядки з `reachable=no` перевести в `status=tested-fail`, `value=0`, додати в `notes` HTTP-код і дату.
- Рядки з `noindex=yes` — те саме, з поміткою `noindex`.
- Не видаляти рядки. Не змінювати `id`, `name`, `tier`.
- Порахувати: скільки живих, скільки мертвих, скільки `noindex`.

**Гейт:** якщо живих < 40% — зупинитися і повідомити, що мережа або список неактуальні.

### Фаза 2 — Пріоритезація (обов'язково)

Згенерувати чергу тільки з тих, що залишились живими:

```bash
node scripts/backlink-queue.mjs --status=todo --tier=S,A --priority=P1,P2 --queue
```

Перевірити, що в черзі немає `tested-fail`. Якщо є — виправити фільтрацію, а не чергу.

### Фаза 3 — Публікація без реєстрації (лімітовано)

Дозволено **максимум 3 публікації за прогін**, тільки Tier A, тільки через офіційний API.

**3.1. Telegraph (єдиний гарантований канал)**

API (акаунт анонімний, це дозволено платформою):

1. `POST https://api.telegra.ph/createAccount` з `author_name`, `short_name` → `access_token`.
2. `POST https://api.telegra.ph/createPage` з `title`, `content` (масив Node), `author_name`, `return_content=true`.

Вимоги до кожної сторінки:

- 500+ слів, унікальний текст, **не** копія лендінгу;
- рівно **1** посилання на домен, анкор різний на кожній сторінці;
- тема різна, взята з наявних матеріалів сайту:
  1. «Скільки часу потрібно на злам пароля» → `/password-statistics-2026`
  2. «Парольна фраза чи складний пароль» → `/en/guides/passphrase-vs-password-entropy`
  3. «Що насправді вимагає NIST 800-63B» → `/en/guides/secure-password-generator-guide`
- без «best tool 2026», без списків конкурентів, без клікбейту.

**3.2. Інші Tier A**

Rentry, Write.as, HackMD — публікувати **тільки** якщо знайдено офіційну документацію API, яка явно дозволяє анонімну публікацію. Якщо ні — `blocked`, без спроб через браузер і капчу.

**Заборонено:** створювати більше 1 сторінки на платформу, дублювати текст, публікувати 10+ сторінок «для обсягу».

Після кожної публікації записати URL у `docs/link-building-tracking.json` зі статусом `pending_verification`.

### Фаза 4 — Верифікація (обов'язково для кожного URL)

```bash
node scripts/backlink-queue.mjs --verify=<URL>
```

Для кожного опублікованого URL зберегти **сирий JSON-вивід** у звіт. Критерії:

- `http` = 200;
- `noindex` = false;
- `found` ≥ 1;
- у `links[].rel` зафіксувати фактичний `rel` (порожній = dofollow).

Якщо `found = 0` — статус `failed`, не зараховувати. Не «виправляти» звіт вручну.

Оновити `link_type` у CSV фактичним значенням.

### Фаза 5 — Підготовка людського handoff (обов'язково)

Для Tier S/C/D, які потребують акаунта, підготувати (не виконувати!):

- топ-10 дій на наступний тиждень, по одному рядку кожна: ID, дія, URL, що саме потрібно від людини, орієнтовний час;
- готовий текст для 3 карток каталогів (name/tagline/short/long/tags) — українською та англійською;
- готовий текст одного посту для DOU або dev.to з canonical-посиланням;
- список джерел, які треба перевірити вручну (`status=verify`), з причиною.

### Фаза 6 — Звіт

Створити:

- `docs/link-building-run-<YYYY-MM-DD>.md` — людський звіт;
- `docs/link-building-run-<YYYY-MM-DD>.json` — машинний, з тими самими цифрами.

## 4. Жорсткі правила

1. **Не вигадувати дані.** Кожна цифра в звіті має бути або з виводу команди, або з CSV.
2. **Не вигадувати URL.** Якщо публікація не вдалась — `failed`, а не «ймовірно опубліковано».
3. **Не обходити захист.** Captcha/логін = `blocked`.
4. **Не чіпати чужі зміни.** `git status` перед стартом; не ревертувати незакомічене.
5. **Не комітити.** Залишити зміни в робочому дереві, перелічити їх у звіті.
6. **Ліміт часу — 90 хвилин.** Не встигли — зупинитись і звітувати про виконане.
7. **Мережа недоступна** — зупинитись, не імітувати результати.
8. **Жодних секретів** у звіті, логах, прикладах.

## 5. Definition of Done

- [ ] `docs/backlink-sources.checked.csv` існує, містить усі 256 рядків з `http_status`.
- [ ] `docs/backlink-sources.csv` валідний: 256 рядків, 13 колонок, без дублів `id`.
- [ ] Мертві/`noindex` джерела переведені в `tested-fail`, не видалені.
- [ ] Опубліковано ≤3 сторінки, кожна 500+ слів, різна тема, 1 лінк.
- [ ] Для кожного опублікованого URL є сирий вивід `--verify` з `found ≥ 1`.
- [ ] `docs/link-building-tracking.json` оновлено фактичними URL і `rel`.
- [ ] Звіт `.md` і `.json` створені, цифри в них збігаються.
- [ ] Є розділ «Заблоковано» з причинами (акаунт/captcha/ToS).
- [ ] Є топ-10 handoff-дій для людини.
- [ ] `git status` показує лише дозволені файли (docs/, scripts/, без `src/`).

Якщо якийсь пункт не виконано — у звіті має бути рядок `NOT DONE: <пункт> — <причина>`.

## 7. Умови зупинки

Зупинитися й одразу звітувати, якщо:

- живих джерел < 40%;
- 3 спроби публікації поспіль провалились;
- з'явився запит на логін, оплату або captcha;
- минуло 90 хвилин;
- будь-яка дія вимагає змінити `src/` або залежності.

## 8. Що отримає людина в кінці

1. Список фактично live-сторінок із доведеним `rel` і `noindex`.
2. Список мертвих джерел (більше не витрачати час).
3. Топ-10 наступних дій з оцінкою часу.
4. Готові тексти для каталогів і блогу.
5. Чесну цифру: скільки referring domains додано за прогін (очікувано 0–3, це нормально).
