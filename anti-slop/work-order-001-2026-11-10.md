## 1. Загальні правила виконання

1. Em dash (U+2014) не використовувати ніде в новому тексті: ні в коді, ні в коментарях, ні в цьому документі, ні в комітах.
2. Заміна в наявному тексті робиться за змістом: кома, двокрапка, дужки або нове речення. Механічна заміна на дефіс заборонена.
3. Ніяких скриптів, що патчать файли (R-33). Усі зміни вносяться в джерело.
4. Переклади в 12 локалях зберігають зміст. Не скорочувати речення заради символу.
5. Не чіпати файли поза обсягом. Не змінювати SEO-значення metadata, hreflang і canonical.
6. Не додавати нових залежностей. Пункт 8 має зменшити кількість іконкових бібліотек, а не збільшити.
7. Після кожного блоку: `npm run build` і відповідні тести зелені.
8. Коміти окремо за фазами, повідомлення англійською, без em dash.

### 2.2 Пункт 2, R-37: створити `DESIGN.md`

Зафіксувати наявний напрям, не змінюючи вигляд:
- Ідентичність: інструмент, а не SaaS-лендінг. Один фокус на екрані, генератор.
- Палітра: `#2A4E63` (primary), `#E5F6FF` (surface accent), `#05a9ff` (accent), `#38beff` (hover у темній темі). Нейтралі окремо.
- Типографіка: Arsenal для заголовків (читабельний, не дефолтний Inter), Varela Round для дрібних підписів, Noto для CJK. Обґрунтування одним рядком на кожен.
- Радіуси: шкала, де пігулка зарезервована за полем пароля як identity motif.
- Діали: `ENERGY 2 / RHYTHM 2 / MOTION 1`.
- Причина кожного великого рішення одним рядком (R-31).
- Посилання на файл з `AGENTS.md`: «для UI читати DESIGN.md, потім antislop».

Критерій приймання: файл існує, містить 3 діали, палітру, шрифти, шкалу радіусів і не суперечить наявному вигляду.

### 2.3 Пункт 3, R-39: курсор для контролів

У `src/styles/index.css` додати один базовий блок:

```css
a[href],
button:not(:disabled),
summary,
select,
label[for],
input[type="checkbox"],
input[type="radio"],
[role="button"] {
  cursor: pointer;
}

button:disabled,
[aria-disabled="true"] {
  cursor: not-allowed;
}
```

Критерій приймання: усі кнопки, акордеони, таби й перемикач теми показують pointer; вимкнені показують not-allowed.

## 5. Перевірка перед здачею

Команди:

```bash
npm run build
npm test
npm run test:components
npm run antislop
npm run seo:locales
npm run secrets:scan
```

Ручна перевірка в браузері (записати результат по кожному пункту):
1. Генерація пароля: password_generated, без помилок консолі.
2. Copy: успіх дає снекбар, заблокований буфер дає помилку.
3. Bulk: відкрити, змінити кількість, закрити Escape, фокус повертається.
4. Вибір режиму (Characters / Words / PIN) і слайдер.
5. Перемикач теми: обидві теми, фокус видно в обох.
6. Шапка: мобільне меню відкривається й закривається.
7. FAQ-акордеон: відкривається з клавіатури.
8. Сторінка гайду й сторінка статистики: без помилок, без em dash у тексті.
9. `prefers-reduced-motion`: конфеті не запускається.
10. Lighthouse на `/en`: accessibility, best-practices, SEO без регресій.

Обмеження перевірки: мобільні 375 px не емулюються інструментом браузера. Якщо зміни зачіпають верстку, перевірити 320 px і 375 px вручну або через DevTools і записати це в звіті. Не писати «перевірено», якщо не перевірено.
